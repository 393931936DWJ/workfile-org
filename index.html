01 — 总流程

任何任务，先过五个关卡

这套流程保证每一步都有依据，而不是靠印象推进。

探查

  • 先完整读取全部输入材料，核实版本、名词、接口
  • 读不到就先解决读取问题，不用二手摘要代替

约束

  • 守住点名的技术栈、结构、格式、交付形态
  • 偏离需先说明理由并取得同意

证据

  • 每个数字来自输入、信源或可复现计算
  • 合计换算用工具算，外部事实附来源

执行

  • 受阻时换通道，不降级交付物
  • 同类错误查共同成因，不掩盖 warning

验证 → 交付

  • 用与生成不同的路径回读、跑测试、抽样重算
  • 交付时写明产物名、路径、打开方式
02 — 核心方法

四套方法

建文件、命名、分析、整理——这四件事统一了我的整个工作流。

① 建文件 · 结构

  • 交付物统一归入主工作目录
  • 每个任务一个独立项目文件夹，不散落在根目录
  • 项目内按需建 原始资料 / 产物 / 总结 子目录
  • 更新文件不覆盖旧版，新建带版本号的新文件

② 命名 · 规则

  • 项目文件夹：YYYYMMDD---项目名
  • 日期 8 位纯数字，禁止横杠
  • 版本文件：原文件名（第X版）
  • 总结文件同样按日期+内容命名

③ 分析 · 方法

  • 数据分析走：明细 → 汇总 → 排序 → 归因
  • 可比较信息优先用表格呈现
  • 汇总由明细现算，跨产物并排核对
  • 结论不超出检查范围，主动找反证

④ 整理 · 归档

  • 资料按「原始 / 产物 / 总结」分类
  • 关键业务数据做双备份，记录双表 ID
  • 同步冲突时列出来源交人拍板，不静默覆盖
  • 批量产出继承统一规范，尺寸量化
03 — 命名规范

命名即归档

这是我个人最看重的硬规则：命名方式决定了文件好不好找、能不能复用。

项目文件夹

YYYYMMDD---项目名硬性

日期 8 位纯数字，禁止横杠；必须有日期前缀 + 内容，禁止纯日期名、禁止无日期前缀。

版本文件

原文件名 + 中文 （第X版）

如 RFQ_TECHNICAL_DETAILS_已填报价_第四版.xlsx，更新不覆盖旧版。

命名示例
# 正确的项目文件夹命名
20261005---京东旗舰店关键词月度汇总报表
20261004---舜红天猫客服话术学习

# 错误的写法
2026-10-05---项目  # 日期带横杠
项目文件夹  # 无日期前缀

# 版本文件
RFQ_TECHNICAL_DETAILS_已填报价_第四版.xlsx
